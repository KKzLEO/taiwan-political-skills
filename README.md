# 台灣訊息查核 skill

收到一則訊息，想知道是真是假？這個 skill 會把它拆成一句一句可以查證的說法，請一個 AI 當正方查證，再派三個 AI 當反方專門挑毛病，最後找另一家公司的模型來交叉抗辯。分數由程式依固定規則算出來，同一份結果每次都得到同樣的分數。

可以在 **Claude Code** 和 **Codex** 裡使用。

## 它會做什麼

- **查核四種輸入：** 新聞網址、LINE 轉傳文字、截圖、影片連結（YouTube 等，需要 `yt-dlp`，只用上傳者自己放的字幕）
- **一個正方對三個反方：**
  - 反方 A 檢查證據
  - 反方 B 自己去找反證
  - 反方 C 檢查有沒有偏向任何一方
- **跨模型抗辯：** 自動偵測電腦上的 Codex 和 Claude Code，請另一家公司的模型當外部反方
- **溯源：** 最早在哪裡出現、有哪些版本、是不是舊聞新炒
- **背景查核：** 媒體信任度（Reuters 調查）、學術研究對媒體立場的分類（有研究才列）、記者署名、用詞是否中立
- **查核機構也要被查核：** 事實查核中心、Cofacts、MyGoPen 的結論只當線索，會回到原始資料重新驗證
- **操弄手法辨識（實驗功能，報告不列）：** 例如斷章取義、舊圖新用、假語錄、急迫轉傳，並告訴你下次怎麼自己認出來。同一則訊息換政黨或重跑一次，標記可能不同，所以報告不列，要另外產生一份才看得到，見「已知限制」
- **法條：** 一定引用條文原文，標明「非法律意見」

## 報告長這樣

下面是一則 LINE 轉傳「立法院昨天三讀通過，以後騎機車一律要開大燈，沒開罰三千！快轉給家人。」的實際結果（2026-11-20，Claude Code 當主體、只照 SKILL.md 從頭做到尾，花了 48 分鐘），完整紀錄在 [examples/](examples/)：

```text
錯誤 ▲━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 正確
     0
```

**結果：不符｜可信度 0｜信心度 高（100）｜完整模式・跨模型 1 席｜可公開**

報告的內容依序是（沒有內容的段落不會出現）：
- 結論
- 查核範圍和限制
- 逐項判定
- 溯源
- 報導品質
- 操弄手法（只有一段說明，不列標記）
- 和既有查核的比對
- 辯論後的修正（和前文不同時以這裡為準）
- 爭議點
- 已檢驗的質疑
- 法條
- 評分拆解
- 每一筆來源
- 執行紀錄

## 三個數字

| | 意思 | 會受什麼影響 |
|---|---|---|
| **可信度** 0–100 | 這則訊息本身有多正確 | 只看每個命題的判定。以主要說法為準，其他說法只會把分數往下拉；主要說法對、但有細節錯，最高「大致符合」 |
| **查核結果** | 符合／大致符合／部分符合／不符／無法判定 | 由可信度換算。主要說法有一半以上查不到、也沒有被證明是錯的時，判「無法判定」，因為查不到不等於假的 |
| **信心度** 0–100 | 這次查得多扎實 | 缺少第一手證據、沒有跨模型反方、覆核沒通過、來源被擋、拿不到法條原文、快速模式，都會扣分 |

媒體立場、記者署名、用詞、操弄手法**都不會影響可信度**。看是哪家媒體就先打折，正是我們要避免的偏見。

完整規則在 [skills/factcheck/references/scoring.md](skills/factcheck/references/scoring.md)。

## 安裝

需要 Python 3.11 以上，不用另外裝任何套件。影片查核需要 [yt-dlp](https://github.com/yt-dlp/yt-dlp)。目前只在 macOS 上實測過；Windows 請在 WSL 裡使用。

**Claude Code：**

```
/plugin marketplace add <GitHub 帳號>/taiwan-political-skills
/plugin install taiwan-factcheck@taiwan-political-skills
```

**Codex：**

```bash
git clone https://github.com/<GitHub 帳號>/taiwan-political-skills.git
mkdir -p ~/.codex/skills
ln -sfn "$PWD/taiwan-political-skills/skills/factcheck" ~/.codex/skills/factcheck
```

**建議另外裝一個不同公司的模型 CLI**（Claude Code 使用者裝 Codex，Codex 使用者裝 Claude Code），否則信心度固定扣 20 分，報告也不能標「可公開」。

法條一律到全國法規資料庫查原文。角色在隔離的子程序裡跑，用不到法規 MCP。

## 使用

直接說「幫我查核這則訊息」，然後貼上內容或網址就可以了。

**跑評測前先看額度：** 2026-11-18 第二輪評測 29 個工作同時跑 5 個，2 小時 22 分鐘就用完一個 Claude 帳號的每週額度。2026-11-20 最後一批 18 個完整流程同時跑 3 個，跑了 3 小時 26 分鐘，最後 3 個因為每週額度用完而中斷（同一週稍早還做了別的工作）。要分批跑，或改用 API key。

**很花時間和額度：** 完整模式實測（2026-11-20 最後一批，12 則；主模型的角色用 Claude Fable 5.2、推理強度 xhigh，外部反方用 Codex、推理強度 high）：每則 26 到 62 分鐘，中位數 42 分鐘。Claude 的角色每則用掉 240 萬到 890 萬 token（含快取讀取），照 API 定價換算是 16 到 33 美元；Codex 每則 16 萬到 29 萬 token。更早幾輪用的是別的模型，Codex 的角色當時實際上是推理強度 none，量到的是 20 到 90 分鐘，不能直接比。想快一點就說「快速查核」。快速模式只有一席反方，只實測過一次（2026-11-20，一則短截圖，18 分鐘），而且報告不能標「可公開」。

**用 `claude -p` 無人值守執行時要多設一個環境變數：** Claude Code 的無人值守模式預設會在最後一次回覆的 10 分鐘後，停掉還在跑的背景指令（它會印出 `Background tasks still running 10m after the last turn`），而這個 skill 的一個角色常常跑超過 10 分鐘。啟動時加上 `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0`。平常在 Claude Code 裡對話使用不受影響（2026-11-20 實測，Claude Code 2.1.329）。

每次查核都會在目前的資料夾底下產生 `factcheck-runs/<日期>-<主題>/`，裡面有完整的中間紀錄，任何人都可以檢查一份報告是怎麼得出來的。

## 已知限制

- **有些角色看得到你自己的設定**（2026-11-18 金絲雀實測，見 `evals/results/2026-11-18-isolation.md`）：
  - `claude -p` 一律加 `--safe-mode`，看不到 `~/.claude/CLAUDE.md`、hooks、外掛和 MCP，網路搜尋照常。
    - 需要支援這個參數的 Claude Code 版本。主體是 Claude Code 時，舊版會在第 2 步失敗並印出原因；Claude Code 當外部模型時，`fc.py detect --probe` 就會印出原因。
    - 企業管理的設定和受管外掛的 hooks，在這個模式下仍然有效。
  - `codex exec` 一定會讀到 `~/.codex/AGENTS.md`，目前沒有參數關得掉。Codex 當主體時，主模型的角色（讀入與拆題、溯源、正方、反方 A/B/C 和它們的覆核、答辯、裁判）都讀得到它，報告的「查核範圍和限制」會寫明；Codex 當外部反方時，席位表照探測的回答標隔離程度（回答讀得到設定是「部分隔離」，沒有回答是「未確認」）。要完整隔離，另外準備一個乾淨的 Codex 設定，自己登入一次，再用 `FC_CODEX_CMD="env CODEX_HOME=$HOME/.codex-factcheck codex"` 指定。這個指令會原樣寫進 `models.json`，分享查核資料夾時會帶出你的帳號名稱。
  - **Codex 的角色不讀你的 Codex 設定**（為了隔離加了 `--ignore-user-config`），`~/.codex/config.toml` 裡的模型和推理強度不會套用。沒有指定時用 Codex CLI 的預設模型，推理強度是 `high`；要換模型設 `FC_CODEX_MODEL`，要換強度設 `FC_CODEX_EFFORT`，再重跑偵測。報告的席位表會寫出每一席用的模型和推理強度。
  - **角色讀不到你電腦上的檔案**（2026-11-20 實測）：`claude -p` 的角色只有網頁搜尋和網頁讀取兩個工具（`--tools "WebSearch,WebFetch"`）；`codex exec` 的角色關掉了 shell 工具。不加的時候，兩種角色都讀得到電腦上的檔案；加了之後讀不到本機的文字檔，搜尋照常。Codex 其他內建工具有沒有關掉，沒有逐一實測。
  - 在 Claude Code 裡執行時，辯論角色也用 `claude -p --safe-mode` 跑，看不到你的 CLAUDE.md 和專案記憶。終端機裡要有 `claude` 指令；只裝了桌面版時會停下來，請你安裝命令列版本，或用 `FC_CLAUDE_CMD` 指定路徑（這個路徑同樣會原樣寫進 `models.json`）。
  - 讀入和拆題也用獨立的子程序跑。主體只負責把你給的內容原封不動交給程式；截圖上的文字由主體照抄，只抄寫、不判斷。
  - 席位表的「隔離」欄是模型自己回報的，不是金絲雀實測。
- **不判斷圖片或影片是不是偽造的，** 只查內容說了什麼。
- **影片只用上傳者自己放的字幕。** 自動產生和機器翻譯的字幕不採用；影片沒有上傳者自己放的字幕時，要你自己提供逐字稿。抓字幕失敗時，會照實印出 yt-dlp 的錯誤；中文字幕沒抓到、只抓到英文這種排在後面的字幕時，也算抓字幕失敗，不會拿可能是翻譯的字幕當成當事人的原話。逐字稿和影片對不對得上不會另外查核，人名或數字轉錯會直接影響結果。
- **社群平台常常抓不到原始貼文，** 這時會請你貼上連結或截圖。
- **網址輸入不保證讀到逐字全文：** 網址的全文由子程序用網頁工具讀，可能只讀到片段或摘要，報告的「查核範圍和限制」會寫明，讀入時記下的限制也會列在那裡。重要的報導請直接貼上全文。
- **主旨錯、前提真的訊息，結論可能偏高。**
  - 2026-11-18 第一輪的標準案例裡，有兩則主旨錯誤的訊息拿到「部分符合」，而且報告標了「可公開」。原因是拆題太細，真的細節稀釋了錯的主旨。
  - 第二輪改了拆題規則，也讓命題重要性可以挑戰。舊案例從 10 則對 7 則進步到 8 則（用當時的評測腳本和舊規則跑的，不是現在交付的流程）。
  - 2026-11-19 計分改成主旨優先：以主要說法為準，其他說法只會把結論往下拉，有任何命題判錯就最高「大致符合」。這是看過現有案例才設計的，驗證結果見 `evals/results/`。
  - **「可公開」不保證結論正確：** 2026-11-19 第一批新案例 6 則有 4 則結論錯卻標「可公開」；改成主旨優先之後，第二批 6 則剩 1 則（兩批都是當時的流程跑的）。2026-11-20 用現在的流程跑 12 則沒看過的新案例：結論完全相同 10 則、差一級 2 則；標「可公開」的 5 則，結論都和答案相同（`evals/results/2026-11-20-final.md`）。12 則不多，不能保證以後不出錯，報告標「可公開」時還是會另外提醒。
  - 貼出結論前，請先看「逐項判定」的重要性和判定，詳見 `evals/results/`。
- **時間和動機（2026-11-19）：**
  - 沒有日期的轉傳訊息，工具會另外檢查兩件事：訊息叫你趕的期限過了沒、訊息說的「剛剛」「最新」是不是真的最近。期限過了，結論是「不符」；舊消息說成新消息、內容本身正確，最高是「大致符合」。這兩種情況報告都會在結果行下方寫明。
  - 期限已過、但內容本身是真的訊息，結論是「不符」，報告不會標「可公開」，並寫出不看時間的結論。
  - 拆題漏掉時間的檢查時，報告的「查核範圍和限制」會寫「時間命題：沒有」。看到這一行、訊息又明顯在講時間，請自己多留意。
  - 「他這樣做是為了…」這類對動機的猜測算意見，不在結論內；報告會在結果行下方列出哪幾句不在結論內。
- **只有結論是「符合」或「不符」的報告才可能標「可公開」。** 「大致符合」「部分符合」「無法判定」的報告，逐項判定和出處可以引用，整則結論不要拿去公開貼文。
- **主旨是真的、但細節大多查不到的訊息，結論可能偏低：** 「無法證實」的係數（0.35）比「部分錯誤」（0.5）低，查不到的細節會把結論拉到「部分符合」，即使沒有任何一條判錯。
- **主要說法剛好一半查不到時原本是「無法判定」；** 如果另外有一條重要性 4 的關鍵事實判「錯誤」，會改成照分數給結論，可能是「大致符合」。
- **事實類的命題如果被判成「非事實陳述」，一樣不計分，** 而且沒有「結果取決於分類」那道防線（見計分規則的「可公開」）。看報告時留意重要性最高的命題有沒有被判成非事實陳述。
- **操弄手法的標記沒有通過跨陣營一致性驗證，報告不列：**
  - 2026-11-20 發版前的最後一批：一則帶期限的訊息換三個政黨，結論、計分命題的判定、可信度都一樣，但其中一版多標了一個手法（情緒煽動與恐慌）。只重跑溯源那一步（每版共 4 次），同一則訊息原封不動重跑，標記就可能不一樣，而且不能排除和政黨有關（國民黨版標得比另外兩版少；次數太少，下不了結論）。另一則探測三個版本的標記相同。每一版的次數見 `evals/results/2026-11-20-final.md`，更早幾輪的經過見 CHANGELOG。
  - `report.md` 不列手法標記，只留一段說明。要看的話，執行 `fc.py render --run <查核資料夾> --with-tactics`，會另外產生一份 `report-with-tactics.md`；標記只當成提醒自己留意的線索，**不要引用在公開貼文，也不要拿來比較不同陣營的訊息**。
  - 擋不掉的：裁判寫的理由偶爾會順帶提到手法（最後一批 18 份報告裡 4 份），一樣只當線索。「結論」裡判定後面括號的「斷章取義」「舊聞新炒」是那一條命題判定的一部分，不是手法標記；它換政黨時穩不穩，還沒有量過。
- **「可公開」會受覆核細節影響：** 覆核者只要指出一處理由寫得不精確，信心度就扣 10 分，可能從「可公開」掉到不能公開。
- **分數門檻是第一版的數字，** 會用 `evals/` 的標準案例持續校正。
- **發版前的評測還沒做完**（每一項的狀態見 `evals/README.md`）：個人設定寫了偏好會不會影響判定、同一則跑三次的重現性、同一則訊息由 Claude Code 和 Codex 各當一次主體的比對，都還沒做（兩個主體各自從頭跑完一則不同的訊息，2026-11-20 做過，見 `evals/results/2026-11-20-hosts.md`）；誘導式提問和訊息裡夾帶指令，現在的流程只測了讀入與拆題那一步（2026-11-20），完整流程沒有測；快速模式只跑過一則。
- **Gemini CLI 還沒有實測過，預設不會入席。** 它的指令沒有隔離和鎖工具的參數；實測之前不把它算成跨模型席位。

python3 -m unittest discover -s tests -t .

**資料可以提 PR 修正，但要附出處：**
- `skills/factcheck/data/tw/media.toml` 每一筆都要有出處網址；信任度和立場研究另外要有年份，紀錄要有日期。紀錄（例如 NCC 處分）這一版先不印在報告上：目前只有一家媒體有紀錄，等收錄標準訂好、每一家都照標準查過之後才顯示。
- `tactics.toml` 每種手法的案例，至少要涵蓋兩個不同的被攻擊方。

這兩條規則都由測試強制檢查。

**English summary:** An open-source fact-checking skill for Claude Code and Codex, focused on Taiwan. One proponent agent is attacked by three opponent agents (evidence, counter-evidence, neutrality lenses), plus each available cross-vendor model as an external opponent. A clean-context judge rules on each attack, and deterministic scripts compute a reproducible credibility score, a verdict, and a separate confidence score. Code is MIT; data is CC BY-SA 4.0.
