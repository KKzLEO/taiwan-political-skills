# 中立化：產出 `claims.json`

把 `source.json` 的內容拆成**原子命題**：每一項只包含一個能被證據支持或推翻的說法。

## 怎麼拆

> 某法案已經三讀，所以某公司拿到訂單，明年營收一定大增。

至少拆成三項：法案是否三讀（事實）、該公司是否拿到訂單（事實）、營收一定大增（預測）。不要把「政策方向存在」當成「特定公司已經接單」。

### 拆題規則

前兩條由程式檢查，沒通過會退回重拆。

1. **`original` 逐字照抄訊息裡的一段。** 比對時會忽略標點、空白和逐字稿的時間碼，但字要一樣。數字和旁邊的符號（小數點、斜線、負號、％）要原樣照抄，連中間有沒有空白都一樣。
2. **明說的命題（F、S）在原文的位置不能重疊。**
   - 一句話不能同時有整句的命題和片段的命題。
   - 一句話裡有幾個能各自成立或不成立、而且訊息都要讀者相信的主張，才把這句切成不重疊的幾段，每段一個命題。例如「民進黨獲得 4,984,060 票，占 36.16%」切成「民進黨獲得 4,984,060 票」和「占 36.16%」。
   - 修飾語和前提（例如「立法院三讀的」）跟著它修飾的主張，不另外拆。
3. **隱含命題（I）：** 寫出訊息想讓讀者相信、卻沒有明說的主張。例如「三讀通過，以後一律要開大燈」暗示「已經生效」。
   - 它可以和明說的命題共用原文，也可以橫跨好幾段，但同一段文字只能有一個隱含命題。
   - 前提和背景不另外寫成隱含命題。例如「感謝某議員爭取」，不另外寫成「這項建設是某議員爭取來的」。
4. **引述：** 「某人說了某句話」整段是一個命題。
   - 訊息的重點是「他說了這句話」時，查他有沒有這樣說、意思有沒有被改。
   - 引號裡是一項可以查證的事實、而且訊息要讀者相信它時（例如「某立委質詢指出『台電虧損 2000 億』」），整段仍是一個命題。判定看引號裡的內容，判法見共同規則；他有沒有說過，寫進理由。
5. 意見、預測、口號（O、P、U）不計分，可以和計分命題共用原文。
   - **對別人動機或目的的推測**算意見（O）：訊息猜測別人心裡「為什麼這樣做」「想達到什麼」（「是怕通過」「只想贏錢」「為了救某人」），而且沒有引用當事人自己的說法或正式文件。
     - 同一句話有「做了什麼」也有「為什麼」：拆成兩條，做了什麼是事實命題，為什麼是 O。
     - 可以拿紀錄或資料檢驗的說法**不是**動機推測，仍然是事實或隱含命題：具體行為（收錢、關說、下指令、刪預算）、因果和差別待遇（「因為是某黨的人，所以判得比較重」「刪了這筆預算，所以工程停擺」）。
     - 引述優先：訊息引用第三人對別人動機的說法時，照第 4 條當引述處理。
6. **時間：** 查核日期的定義見共同規則的「時間」。
   - **查得到發布時間時**（新聞網頁的發布時間、截圖上看得到的時間）：
     - 發布時間只看使用者給的內容本身。網路上查到同一則訊息更早的流傳時間，不算這則的發布時間。
     - 相對時間（「剛剛」「今天」「明年」「最新」）依發布時間換成明確的日期，寫進 `neutral` 和 `time_place`。例如發布於 2025 年 9 月的「明年」，寫成「2026 年」。
     - 讀者看得到日期，不寫下面兩種時間命題，`time_claims` 兩個都填 null。
   - **查不到發布時間時**（例如沒有日期的轉傳文字），事件本身照內容拆，不寫日期，`time_place` 註明「發布時間不明」。另外檢查兩件事，各寫成最多一條隱含命題（I），並把編號填進 `time_claims`：
     - **期限前提（`deadline`）：** 訊息叫讀者在某個日期或期限前**去做一件事**（投票、連署、報名、申請、繳費、領取）。呼籲本身照舊是意見（O）；另外寫一條隱含命題，說出「這件事現在還能做」，例如「8 月 23 日的公投還沒舉行」「申請期限還沒到」，`time_place` 寫查核日期。
       - 訊息只是提到一個日期（生效日、活動日期、政策的起訖日）、沒有叫讀者去做事，才不算。
     - **暗示的時間（`relative`）：** 訊息用相對時間（「剛剛」「今天」「最新」「昨天」「去年」）講一件事，讀者會以查核日期為準去理解。寫一條隱含命題，說出訊息暗示這件事是什麼時候的事，例如「這次三讀是查核日期當天發生的」。
       - 只寫「什麼時候」。「通過了沒有、生效了沒有、發生了沒有」是內容，照第 2、3 條寫成一般命題。
     - 有好幾個期限、或好幾個相對時間時，各合成一條：`original` 抄其中一處，其他的寫進 `neutral`。
     - 同一句話兩種都符合（「明天投票，記得去投」）：只寫期限前提。
     - 這兩條的 `importance` 填 3、`core` 填 false。程式另外處理它們（見 scoring.md 的「時間命題」）：判對不加分，判錯才有影響，重要性不影響計分。
   - **沒寫年份的日期**（例如「8/23」）：指的是訊息談的那件事實際發生或預定的日期。查不到是哪一年，`time_place` 寫「年份不明」。

## 每一項的欄位

```json
{
  "prompt_was_leading": false,
  "time_claims": {"deadline": null, "relative": null},
  "claims": [
    {
      "id": "C1",
      "original": "訊息裡的原句，逐字照抄",
      "neutral": "中立改寫：去掉情緒字眼和立場，保留所有限定詞（「可能」「至少」「約」）",
      "type": "F",
      "importance": 5,
      "core": true,
      "legal": false,
      "time_place": "時間和地點",
      "entities": ["人名", "機關", "法條", "數字"],
      "search_seeds": {"pro": ["支持方向的搜尋詞"], "con": ["反面方向的搜尋詞"]}
    }
  ]
}
```

- `time_claims`：兩個鍵都要有。值是第 6 條那兩種隱含命題的編號（例如 `"deadline": "C5"`）；訊息沒有這種時間命題，或內容查得到發布時間，就填 null。
- `type`：`F` 事實、`S` 統計、`I` 隱含（把話裡暗示的事實說出來）、`O` 意見、`P` 預測、`U` 模糊到無法查證。
- `importance`：1–5，這個命題對整則訊息的說服力有多關鍵（量表和共同規則相同）：
  - 5：主旨，訊息最想讓讀者相信或照著做的事，通常一到兩條。
  - 4：直接撐起主旨的關鍵事實，它錯了主旨就站不住。
  - 3：支撐主旨的細節，例如數字、日期、條文內容。
  - 2：次要細節。
  - 1：背景或順帶一提。
- `core`：去掉它，整則訊息的主旨就不成立。
- `legal`：命題的真假取決於法條內容或立法進度。

## 中立改寫的規則

- **限定詞一個都不能少，也不能多。** 原文說「一定」，改寫就是「一定」；原文說「可能」，就不能改成「會」。
- 去掉情緒字眼（「無恥」「又在騙」）、表態用語和反問語氣。
- 不要加入原文沒有的背景知識或你的推測。
- 立場相反的兩則訊息，改寫的語氣要對稱。

## 使用者的提問

使用者問「這是不是又在騙人？」「某黨是不是又造謠？」時，提問裡的立場**不是**待查命題。把 `prompt_was_leading` 設成 `true`，只查訊息本身。
