# 在 Codex 上派出角色

流程和指令見 SKILL.md 的第 2–8 步。第 2 步的讀入與拆題和主模型的席位都跑 `codex exec`：在空的暫存資料夾裡執行，只拿到該角色的指令和輸入資料，看不到這段對話。角色的 shell 工具是關掉的（`-c features.shell_tool=false`）；2026-11-20 實測：不加時角色讀得到本機檔案，加了之後讀不到，搜尋照常。

**隔離程度：** 2026-11-18 的金絲雀實測顯示，子程序一定會讀到使用者的 `~/.codex/AGENTS.md`，`--ignore-user-config` 只會跳過 config.toml。所以主體是 Codex 時，主模型的角色（讀入與拆題、溯源、正方、反方 A/B/C 和它們的覆核、答辯、裁判）都讀得到它，報告的「查核範圍和限制」會寫明。要完整隔離，用 `FC_CODEX_CMD` 指向另一個乾淨、自己登入過的 Codex 設定。這個指令會原樣寫進 `models.json`，分享查核資料夾時會帶出你的帳號名稱。用了自訂的指令時，報告改寫「隔離程度沒有確認」，因為程式不會探測主體自己的 CLI。

**模型和推理強度：** Codex 的角色不讀使用者自己的 Codex 設定（`--ignore-user-config`），所以 `config.toml` 裡設的模型和推理強度不會套用。
- 模型：沒有指定時用 Codex CLI 的預設模型。要換模型，設環境變數 `FC_CODEX_MODEL`。
- 推理強度：依序取 `models.json` 記的強度、環境變數 `FC_CODEX_EFFORT`，都沒有就是 `high`。主體是 Codex 時，第 0 步 detect 帶的 `--host-effort` 也會套用到 Codex 的角色。
- detect 會把實際會用的模型和強度記進 `models.json`，報告的席位表會印出來。要換的話，設好環境變數再重跑第 0 步的 detect。

**等待和逾時：**
- 每個角色要跑幾分鐘到半小時以上。一個 `run-model` 最多會啟動 CLI 4 次（當掉重試一次，格式不對再整個重做一次），每次各有 `FC_TIMEOUT`（預設 3600 秒）的上限。第 5 步整個迴圈算一個指令。
- 你的指令工具有 timeout 參數時，至少設成 `FC_TIMEOUT` 的 2 倍。設不了那麼長，或工具先返回、指令留在背景時，就繼續等它結束，不要重跑同一步，也不要結束這一輪。
- `fc.py status` 會把還在跑的步驟顯示成「缺少」，看到「缺少」不代表失敗。中斷後續跑之前，先確認沒有還在跑的 `fc.py` 程序。
