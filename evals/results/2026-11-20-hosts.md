## 找到的問題

**1. 反方和覆核其實沒有同時跑（已修）。**

- SKILL.md 第 5 步和第 8 步的迴圈寫的是「指令 `||` 印出失敗訊息 `&`」。bash 會把整串放到背景；zsh 只把最後一段放到背景，前面的指令照樣等它跑完。macOS 上兩個主體的 shell 都是 zsh，所以席位是一席跑完才跑下一席。
- Codex 主體自己發現了：反方 A 跑了四分多鐘，其他席位還沒開始。它另外用 bash 啟動其餘三席，過程中停掉自己多開的一個 B 程序（回報裡照實寫了「反方沒有跑起來：B」那一行的由來），四席最後都成功。
- Claude Code 主體沒有發現，四席照順序跑完（結束時間 15:02、15:04、15:09、15:13），結果不受影響，只是多花了大約十分鐘。
- 修法：每一席的指令外面加括號。新增的測試會在 bash 和 zsh 底下實際執行說明書裡那兩段指令，確認每一席都同時啟動。
- 這兩次實測跑的是修正前的說明書。

**2. 無人值守的 `claude -p` 預設會停掉跑超過 10 分鐘的背景指令（寫進 README）。**

- 第一次嘗試時看到它印出 `Background tasks still running 10m after the last turn … stopping them`。這個 skill 的一個角色常常跑超過 10 分鐘。
- 啟動時要加環境變數 `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0`。平常在 Claude Code 裡對話使用沒有這個上限。

**3. 第一次嘗試作廢，和工具無關。** 13:07 開跑，13:10 筆電蓋子被闔上，電腦睡到 14:13。醒來後主體等的背景指令已經斷線。14:40 重新開跑，上表是這一次。
