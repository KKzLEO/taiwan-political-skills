## 四項修改和抗辯

使用者 2026-11-19 核准四件事。每一項的實作，在 CHANGELOG 的「未發布」有詳細說明：
1. 用沒看過的新案例驗證計分規則。
2. 重跑被卡掉的工作。
3. Claude 主體的角色改用獨立程序。
4. 三個小修正：意見、預測、模糊說法不計分；case-013 答案卷以收到訊息那天為準；裁判漏列網址要有退路。

**第一次抗辯：0/3 擋回。**
- **重大問題：**
  - 把事實標成「模糊說法」就能藏起來。例如「物價三年漲了五成」被標成模糊說法，結論會從「不符」翻成「符合」，而且可公開。
  - 溯源攻擊漏列網址時，報告照樣可公開。
  - A、B、C 失敗時默默降級。原本 Claude 主體會整次停下，改用獨立程序之後會繼續跑，還能標可公開。
  - 程式專用的欄位，裁判寫錯格式就會讓結算當掉。
- **其他問題：** 備用的 Agent 做法留著記憶外洩；扣分和爭議點的設計過度；文件和程式說法不一致。

**第二次抗辯（重審）：0/3 擋回。**
- **重大問題：**
  - 「類型和判定不一致」的防線只看「核心或重要性 ≥4」，把重要性壓到 3 就能繞過。
  - 新加的「以查核當天為準」規則，例子和「呼籲判非事實陳述」矛盾，也可能讓新聞裡的「明年」被誤判。
  - 辯論降重要性，可以拆掉防線。
  - 001 變成結論錯卻可公開，不該默默接受。
- **其他問題：** 副作用少算 2 份；沒執行的席位在席位表上寫錯；退路只試最後一次的輸出。

**最終版：** 照第二次審查的最小修法改完，依規定沒有第三次送審。
- **防線：** 改成「把這類命題算進去，結論會不會變」，不看重要性。另外加一條：辯論調整的重要性，不能決定可不可公開。
- **退路：** 從最新的一次往前，逐一試每次讀得到的輸出。
- **時間規則：** 拿掉，只在角色的指令裡寫出查核日期，規則另外設計。
- **detect：** 印出主體的模型；找不到主體的 CLI 時警告；偵測到 API key 時只提醒、不印內容。
- **文件：** 共用流程只寫在 SKILL.md，加上「主模型角色失敗就停下」。

## 新發現、待決定

1. **「可公開」不保證結論正確：** 新程式下 001、009、011 都是結論錯卻可公開。候選規則可以修好這三則，但還沒驗證。在它驗證完之前，可以先加一條只擋公開、不改分數的防線：關鍵命題判錯誤、結論卻不是「不符」，就不能公開。用現有資料推算，這條會擋下 001、009、011、012，都是結論錯的；另外也會擋 holdout 國民黨版，那一則沒有答案卷。
2. **以查核當天為準的規則：** 審查建議的設計是兩點：
   - 呼籲、預測照舊判「非事實陳述」。
   - 訊息叫人在某個日期做事，或用「明天」「明年」這類相對時間時，拆題另立一條隱含命題，寫出它預設的時間狀態，例如「這場公投還沒舉行」。

   case-007 的答案卷是用報導發布當天的標準，要一起決定。
3. **讀入和拆題也改用獨立程序：** 目前第 1、2 步由主體自己做，看得到記憶和對話，和評測的跑法不同。對照探測顯示，拆題的改寫會影響判定。
4. **既有漏洞（不是這次造成的）：**
   - 裁判可以在沒有任何成立攻擊的情況下改掉命題的判定，不會觸發覆核，也沒有標記。
   - 反方輸出格式壞掉時，可能留下標成成功的檔案。不過答辯那一步會跟著當掉，不會產出可公開的報告。
5. **命題層級的跨黨差異：** 對照探測的可信度差 15 分。要知道是不是偏向，每版至少要再跑 2 次。
