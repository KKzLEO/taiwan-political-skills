# 0.2.0 交付標準（2026-11-19，動工之前寫）

使用者的指示是「跑到你覺得可以交付再回報」。這份文件先把「可以交付」寫成可以檢查的條件，之後的修改和評測都對照它，不事後放寬。

## 為什麼不只看「五級結論完全相同」

- 兩位獨立的重判者，對同一批「舊聞當新聞傳」的案例給過不同答案：一次判「部分符合」，一次判「大致符合」。所以相鄰一級的差異，有一部分是答案卷本身的雜訊。
- 對使用者真正要緊的錯誤，是把假的說成真的、把真的說成假的，或者差到兩級以上。這種叫**嚴重錯誤**。

## 條件

1. **程式：** 單元測試全過；程式審查沒有未處理的高嚴重度問題。
2. **最終盲測**（至少 10 則沒用來調規則的新案例，答案卷由看不到工具結果的獨立程序用第一手資料寫成、再由另一個獨立程序複核；從 commit 快照、走真實的 skill 步驟、用使用者的預設模型跑）：
   - 結論完全相同至少 70%；
   - 嚴重錯誤 0 則。嚴重錯誤的定義：
     - 結論和答案差兩級以上；
     - 答案是「符合／大致符合」卻判「不符」，或反過來；
     - 答案可以判定、而且是「符合」或「不符」，卻判成「無法判定」；
     - 答案是「無法判定」，卻判成「符合」或「不符」；
   - 結論錯卻標「可公開」：嚴重錯誤 0 則，相鄰一級的最多 1 則。
3. **中立性：** 換政黨的對照探測（現有的一組，加上一組帶日期的）三個版本結論相同、手法標記相同、可信度差距不超過 10。
4. **真實主體實測：** 全新的 Claude Code 主體和 Codex 主體，各自只照 SKILL.md 完成一次查核，中途不用人介入，產出通過檢查的報告。
5. **文件和範例：** README、SKILL.md、規格、CHANGELOG 和程式一致；`examples/` 用現行格式重跑；版本號更新；已知限制寫清楚。
6. **抗辯：** 最終修改經三方抗辯，過半存活；被擋回時依規定只重審一次，並在 CHANGELOG 記錄。

## 沒達到時

- 逐則找原因，修改要有講得通的原則，不能只為了某幾則。
- 改了規則，就用另一批沒看過的新案例重新驗證；用過的批次只能當回歸測試。
- 帳號每週額度用完時停下來，回報目前的狀態。
